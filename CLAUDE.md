# finmax – notes for working on this repo

Native Android TV Jellyfin client (Kotlin, Compose for TV, Media3, Jellyfin SDK 1.7.1). README.md has the architecture and feature status.

## Build

- Needs JDK 17 and an Android SDK with platform 36 (`ANDROID_HOME` or `local.properties` with `sdk.dir`).
- `./gradlew :app:testDebugUnitTest` runs the subtitle sync tests (pure JVM, no device needed).
- `./gradlew :app:assembleRelease` for anything that will run on the TV; debug Compose is too slow on the target (measured: Movies 93 ms/frame debug vs 23 ms release). Both are signed with the debug key, so either installs over the other. After installing, `adb shell cmd package compile -m speed-profile -f com.finmax` does the ahead-of-time compile Android would otherwise do later in idle maintenance.
- App updates: `Updater` reads the latest GitHub release of `ILostXD/finmax` (`BuildConfig.UPDATE_REPO`). A release needs a tag like `v0.3.0` (compared with `versionName`) and the release APK attached as an asset.
- README screenshots in `docs/screenshots/` are real captures from the owner's TV (JPEG).
- `./gradlew :app:testDebugUnitTest -Pscreenshots` renders every page at 1080p into `app/build/screenshots/` (Robolectric + Roborazzi). `AppScreenshots` runs the whole app against `FakeJellyfin` (an OkHttp interceptor serving an invented library and generated art) and walks it with D-pad keys; `DesignScreenshots` renders Home and details from hand-built state. Use them to check layout from the cloud. They can't show video, animation timing or the player's picture.
- Screenshot-test constraints: Robolectric's native graphics can't draw or decode off the main thread (so art is pre-rendered and Coil decodes on Main with `imageDecoderEnabled(false)`), and ExoPlayer never lets Compose go idle (background video is turned off, and the player is captured last with a hand-driven clock).
- In cloud sessions the wrapper's distribution download can time out; a local Gradle 8.14.3 works the same. Maven Central often answers 429 there: pass an init script (`-I`) that adds `https://maven-central.storage-download.googleapis.com/maven2` to `pluginManagement` and `dependencyResolutionManagement` repositories in `beforeSettings`.

## Gotchas learned on the device

- Every Jellyfin SDK call must go through `IoApiClientFactory` (wired in `FinmaxApp`). The SDK's OkHttp client reads bodies on the caller thread, which throws `NetworkOnMainThreadException` from Compose scopes.
- SDK local discovery must be collected with `flowOn(Dispatchers.IO)`, or the app ANRs.
- `PlayerView` must stay non-focusable, or it swallows D-pad keys.
- Tall headers (details) use custom `BringIntoViewSpec`s (`NoAutoScroll`, `MinimalScroll`): the TV default "pivot" scrolling pushes them off screen.
- Write source files as UTF-8 with LF line endings.
- The Chromecast decodes no AC3, E-AC3, DTS or TrueHD. Both players load Jellyfin's FFmpeg audio decoder (`EXTENSION_RENDERER_MODE_ON`, video renderers kept MediaCodec-only), and the device profile declares those codecs. Files with that audio then direct play instead of being remuxed to HLS with AAC, and that HLS stream carries no subtitles.
- Embedded text subtitles: Jellyfin extracts all of a file's subtitle tracks in one pass, reading the whole file first. That takes minutes from the owner's Google Drive (rclone) mount. In direct play, `PlayerController` lets ExoPlayer render the embedded track until finmax has the text (a 20 min read timeout in `SubtitleSources`), then switches to the finmax renderer for sync control. Jellyfin caches extractions in /config/data/subtitles.
- Owner's server (`ssh andyh@andyserver`): Jellyfin runs in Docker (`jellyfin`, config at ~/mediaserver/jellyfin/config). Every media mount is read-only, so "Save trickplay images next to media" fails ("Read-only file system").
- Moving a playing ExoPlayer to another surface (background video → player) corrupts the picture on the Chromecast. Its Amlogic HEVC decoder migrates its buffers to the new surface and keeps showing stale frames. `AmbientVideo`'s video renderer forces `codecNeedsSetOutputSurfaceWorkaround` (a fresh decoder per surface), and the player re-seeks an adopted player once its SurfaceView exists, so decoding restarts on a keyframe. With that, ADB screenshots of the player show the video area empty (hardware video plane).
- Two engines: ExoPlayer, and mpv (`MpvPlayer`, `dev.jdtech.mpv:libmpv`, a Media3 `SimpleBasePlayer`). With "Automatic", `PlayerController` sets `switchToMpvAt` when the chosen subtitle is embedded ASS/SSA, and the screen replaces itself with `Route.Player(mpv = true)`. mpv exposes one track group per mpv track in file order, so the Jellyfin → track mapping is shared. It draws all embedded subtitles itself (`hwdec=mediacodec` through the `aimagereader` interop, `vo=gpu`), and loads a fallback font copied from /system/fonts. It must report its first frame (`setNewlyRenderedFirstFrame`), or PlayerView's shutter hides the video.
- Frame-rate matching (`DisplayModes`) sets `preferredDisplayModeId` to the current resolution's mode at a multiple of the film's rate (1080p 23.976 Hz = mode 109 on this TV; menus use 96). It pauses while HDMI resyncs, and resets when the player is left (not between episodes).
- The only AV1 decoder is Android's software one (max ~2048×1024), so the profile caps AV1 at the decoder's size: 4K AV1 gets converted by the server.
- `FmTextField`: the inner BasicTextField reports "not focused" when it first appears. Ending edit mode on that put focus back on the top bar, so typing never started. It now ends editing only after the field has had focus, and calls `keyboard.show()`.
- Discover mirrors Home: `DiscoverScreen` (trending carousel, then rows that rise on Down: your requests, trending, genres, popular, upcoming; rows page in more), `SeerrSearchScreen`/`SeerrGenreScreen` (paged poster grids), `SeerrTitleScreen` (details-style page; every request goes through `RequestPanel`, with a season picker for shows). Titles Seerr reports as in the library open finmax's own details page (`mediaInfo.jellyfinMediaId`). `SeerrRequests` holds statuses changed this session.
- Details pages use `GlassBackdrop(live = true)`: the art and the background video (a TextureView, so it can be recorded) are drawn sharp, with blurred copies of the same recording laid over them as the glass, so the glass is the video itself. `frost` adds a plain glass coat when the page scrolls. Anything inside it must fade with Compose (`graphicsLayer { alpha }`), not `View.alpha`: the recording ignores View alpha, so the not-yet-playing TextureView once covered the art in black.
- GPU budget on the Chromecast is a few full-screen passes per frame. A `Modifier.blur`/RenderEffect is recomputed every frame anything on screen animates (full-screen ones held Home and details at ~100 ms a frame), so artwork is blurred once on load (`BlurredImage`, a Coil transformation). The still-art glass (`StaticGlass`) is one Offscreen layer, so its passes are drawn once and reused. The live glass draws the picture sharp once and lays the glass over it as 1/8-size blurred coats with their fade cut in (`DstOut`); those layers must be `CompositingStrategy.Offscreen` (or the cut hits the screen), and gradients inside the scaled layer need explicit `startX/endX`/`startY/endY` (relative ones stretch over the small layer). Measured: Home hero 105 -> 29 ms, details with a clip 109 -> 27 ms. Check with `dumpsys gfxinfo com.finmax framestats`.
- Creating a preview's ExoPlayer blocks the main thread 100-450 ms, so Home arms previews at 700 ms, after the row glide has finished; at 300 ms the glide stalled mid-way and then jumped.
- Subtitles use the app face everywhere: finmax's overlay sets `BodyFont` (a bare `TextStyle` falls back to Roboto), and ExoPlayer's caption style and mpv/libass load `assets/fonts/BricolageGrotesque-Medium.ttf` (`SubtitleFont`), a static Medium cut made from the variable font with fontTools' instancer, because the variable font defaults to ExtraBold and neither can choose a weight.
- Every clickable `Surface` sets `pressedContainerColor`/`pressedContentColor` to its focused colours: tv-material's pressed defaults put light text on a white fill, which flashed white while OK was held.
- Icons inside buttons morph when they change (`MorphIcon`, used by the shared buttons), and text that follows focus fades in (`FocusSwap`) without animating its size.
- Never drive Discover with blind key sequences: a stray OK on a title page sends a real Seerr request (it happened once, for "Model Citizen"). Discover's first Up from the rows doesn't reliably reach its Search button.
- ADB may list a second device (the owner's phone); set `ANDROID_SERIAL` to the Chromecast (`adb-24281HFDD5JJ7R-…`).
- Driving the TV blind with key events is unreliable: the app restores its last page, and Home's first Up doesn't always reach the top bar. Capture a screenshot after each step.

## Test environment (owner's home network, not reachable from the cloud)

- Target: Chromecast with Google TV 4K (Android 14, armeabi-v7a, 2 GB). Over ADB, screenshots don't capture the video layer; inspect the player with `uiautomator dump`.
- Jellyfin server: 12.4 on the LAN. No Bazarr instance has been tested yet.
- The Chromecast runs Compose at ~30 fps even on Movies (`dumpsys gfxinfo`), and the CleanFrame accessibility service the owner has enabled makes every Compose frame rebuild semantics (2-5 ms). Measure with `dumpsys gfxinfo com.finmax reset` / `atrace -a com.finmax view gfx` against Movies as the baseline.
- Device testing needs the owner's PC. Cloud work should be limited to code, unit tests and builds.

## Design

- Branding is always lowercase: **finmax**.
- Palette: black `#000000` base (the owner's choice; the launcher icons and banner sit on black too), Royal Amethyst `#7E49B3`, Steel Mist `#CFCFCF`. Palette, type and shared components: `ui/theme/Theme.kt`, `ui/components/Components.kt`. Use the `Fm` tokens (`Focus`/`OnFocus` for focused fills, `Accent` for amethyst text and rings), never raw colours.
- Artwork pages use `GlassBackdrop`: sharp art on the right dissolving into a blurred, tinted copy under the text on the left (no dark gradients). Panels over art use `GlassPanelBackground`. Controls are pills (`ButtonShape`), cards are 14 dp rounded (`CardShape`). Every button (pill, ghost, icon) rests on one translucent white fill, turns white with dark content when focused, and is `ButtonHeight` tall; labels are not forced to caps. The top bar's round actions and profile picture match a tab's height. The top bar sits at `TopBarTop` so its wordmark lines up with the details header; the profile picture fills its circle and shows a white ring inside it on focus, without growing. Amethyst is for accents only. Icons are Lucide's line set (`Ic` in ui/components/Icons.kt, from `icons-lucide-android`); only the rating stars and the player's play/pause stay solid Material Rounded glyphs.
- Logo sources with transparency are in `assets/` (`finmax_logo_black.png`, `finmax_logo_small_black.png`); the res/ mark, banner and launcher icons are generated from them. The in-app wordmark (`Wordmark`, `finmax_wordmark_frost.png`) is the owner's soft grey-to-amethyst lettering, used untinted.
- Popovers (pickers, track menus) use `Popover`/`PopoverItem` with `Modifier.popoverBlur(open)` on the page behind: no container, a progressive blur and tint toward the right edge. Popovers take focus themselves, keep the D-pad inside (`onExit` cancels), and send Back straight to the page's back handler (Compose would otherwise spend the first Back on leaving the focus group).
- Home (owner's current choice, Netflix-like): only the hero carousel shows at first (by default the art is mirrored so its subject sits left, with title, text and buttons right-aligned; Settings > Home screen > Featured title text switches back to the original left layout) (horizontal: Left on Play / Right on the last button; plain dots under the buttons; stronger backdrop blur). Down slides it away and the rows rise on plain `Fm.Bg`: genre tiles (a top-rated title's art per genre, softly blurred, each tile lettered in a different cut of the brand face), Your Next Watch, Continue Watching, then the rest. Only poster rows pin and widen: genre tiles, Continue Watching and Next Up scroll only as far as needed (`rememberEdgeScroll`), with no dimming. Poster rows widen the focused card into its landscape art and show its facts under the row, with the focused card pinned to the row start. In a row, `RowMotion` drives the card resize and the slide from one 240 ms progress value and re-anchors the list on the new card each frame (`requestScrollToItem` with a negative offset); scrolling by measured deltas while cards resize made it overshoot and spring back. The open card folds back when focus leaves its row. Only the focused row is at full brightness; the others are dimmed. All poster rows share one size. Continue Watching and Next Up cards keep one size and carry their only extra fact inside the art (time left, or the episode number); they get no info line. A card that holds focus for 1.5 s plays a preview over its art (the player is created at 0.3 s and buffers hidden until then, via `reveal`). The preview is one `PreviewHost` layer over the whole page that follows the focused card's bounds, so on hand-off it grows to full screen while playing and then parks its still-playing ExoPlayer in `PreviewHandOff`; the player screen's `PlayerController` adopts it (keeps it as direct play, re-enables text tracks, takes audio focus), so playback never restarts. The player starts without controls in that case. Previews pick the preferred audio language. In poster rows, cards left of the focused one are dimmed like unfocused rows (keyed off focus, so the dim lifts at once). Rows enter on their remembered card, else the card at the row's start (`focusRestorer` fallback), not the geometrically nearest. `AmbientVideo` decodes audio with Jellyfin's FFmpeg extension (`media3-ffmpeg-decoder`, audio only): the Chromecast decodes none of AC3, E-AC3 or DTS, so previews of most files were silent. It also downmixes to stereo itself (no video for unwatched episodes: spoilers); a resumable one plays the title from where you stopped and after 12 s opens the player at that point (`Route.Player.startMs`), and doesn't replay after Back until focus moves to another card. The carousel's current dot fills over 10 s and the slide advances when it is full (paused in the rows or the top bar). Rows enter on the card at their start as the view shows it (rows scrolled off screen lose their remembered index). Between rows `glideTo` (460 ms, 300 ms while a key is held) re-aims every frame and nudges an off-screen row above into view first so Up glides too. Held Up/Down repeats are swallowed while a glide runs, so holding steps row by row; jumping instead skipped rows and once crashed Compose (a lazy item pinned after disposal). Down on the last row is swallowed. Genres that servers spell several ways (Sci-Fi / Science Fiction) are merged in `MediaRepository.genres` and browsed together. Card size animates in the layout phase and image requests use a fixed size (Coil would otherwise reload as the card resizes). The info line under a row appears at full height with a fade: animating its height re-lays out every row below and dropped frames on the Chromecast. Up from the first row or Back returns to the hero. The top bar stays transparent. Horizontal rows elsewhere use `rememberEdgeScroll()` so the first card returns to its start padding.
- Home rows show the age rating as the hero's outlined `Badge` (`MetaLine(badge =)`), and the poster-row synopsis is always three lines tall. The carousel draws only unwatched titles.
- Background video moves between pages through `PreviewHandOff` (a parked, still-playing ExoPlayer with a `film` flag, released if nobody takes it within 8 s). Opening a Home card while its preview plays carries the video onto details (`carryOver`): a clip plays on for 20 s and stops, resume footage carries on into the player. On a movie or episode details page (detail video set to clips, direct-playable), `AmbientVideo` plays the film itself from the resume point. After 12 s, once the page has been idle for 5 s at the top, `GlassBackdrop(clear =)` lifts the glass, the text fades, the video letterboxes (`fit`) and the player adopts the running player. This happens once per page visit (`DetailState.handedOff`).
- Player (Netflix's layout with the top bar mirrored): title top left; Back and Play from beginning top right, with the focused one's label under them. At the bottom: the play/pause button (where focus rests), elapsed time, a pill-shaped timeline (played and loaded parts round-ended) and time left. Left/Right on the play button, or with nothing on screen, opens the scrub view: the film pauses and everything else hides. A strip of Jellyfin trickplay thumbnails (10 s grid, faster while held) sits over the timeline. OK jumps there and plays; Back returns to where you were. The thumbnails need trickplay generated on the server, which is off by default; without it only the timeline shows. Subtitles hide while scrubbing or loading. Below the timeline, centred, sit preset chips: the main audio, the same with subtitles, and one other language; `selectTracks` restarts a converted stream only once. Then Other… (every audio/subtitle track) and a gear (speed, subtitle timing & sync, playback info). Waits darken the picture with an amethyst spinner and no text, shown after 300 ms and never for an adopted player; while it shows, nothing else does. Paused and untouched for 10 s, the picture darkens and a "You're watching" title (logo, facts) appears on the left under the controls, which stay; any key lifts it and does its usual job. The age rating shows top left when the picture starts (`RatedTag`): the accent line grows from its middle, then "RATED X" rises into view from below its clipped edge; it leaves in reverse.
- Details page scrolling is explicit (`NoAutoScroll` on the column, sections snap by key order, rows inside use `MinimalScroll`).
- `AmbientVideo` (details background) must stay a `TextureView` that is never focusable, and must only hold a player while its page is the top of the back stack, so it never competes with the real player for the decoder.
